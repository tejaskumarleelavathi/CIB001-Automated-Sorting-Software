## 5. Camera Concepts — What They Mean for This Project

This is a plain-English reference written specifically for the CIB overhead camera (TRI245S-C)
and the backlight imaging setup. No photography background assumed.

---

### The one-line version
The camera collects light. Too little light = dark image. Too much = white blown-out image.
You have four knobs to control how much light hits the sensor. Three are software (exposure time,
gain, aperture) and one is physical (focal length / focus).

---

### 1. Exposure Time (Shutter Speed)
**What it is:** How long the sensor stays "open" collecting light, in microseconds (µs).
- 1000 µs = 1 ms = 1/1000th of a second (fast, less light)
- 100000 µs = 100 ms = 1/10th of a second (slow, more light)

**In arena_api:**
```python
nm["ExposureAuto"].value  = "Off"        # take manual control
nm["ExposureTime"].value  = 10000.0      # 10 ms — start here for backlight imaging
```

**For this project:**
- Backlight imaging (overhead camera): specimens are still, so you can use a longer exposure
  without motion blur. Start around 5000–20000 µs and adjust.
- If image is too bright (blown out, mean > 200): reduce exposure time
- If image is too dark (mean < 30): increase exposure time
- The TRI245S-C range is 45 µs – 231597 µs

**What we saw today:** lens cap was on so the camera was at max exposure (231597 µs) trying
to find light. After cap removed + auto-exposure, it settled to a reasonable value and the
image looked correct.

---

### 2. Gain
**What it is:** Digital amplification applied to the signal after exposure. Like turning up
the volume — it amplifies both signal AND noise.
- Gain = 0 dB → no amplification (cleanest image)
- Gain = 24 dB → signal boosted significantly but image gets grainy

**In arena_api:**
```python
nm["GainAuto"].value = "Off"
nm["Gain"].value     = 0.0    # always prefer 0 — only raise if exposure is already at max
```

**For this project:** keep Gain at 0. The backlight provides plenty of light. Only raise gain
if you are at max exposure AND still too dark (shouldn't happen with the backlight on).

---

### 3. Aperture (f-stop)
**What it is:** The size of the opening in the lens that lets light through.
Written as f/2.8, f/4, f/8, etc. — **lower number = bigger opening = more light**.

**Important:** on machine vision / industrial lenses like the ones on the TRI245S-C,
aperture is a **physical ring on the lens barrel** — you set it once and leave it.
It is NOT controllable in software via arena_api.

**Two effects:**
1. Light — bigger aperture (lower f-number) = brighter image
2. Depth of field — bigger aperture = shallower focus (only a thin plane is sharp)
   For flat specimens in a dish, you want a SMALL aperture (f/8–f/16) so everything is sharp.

**For this project:** set the lens aperture ring to f/8 or f/11. Specimens in the sorting dish
are flat so shallow depth of field isn't a concern, but a smaller aperture gives sharper edges
across the whole frame. You will then compensate with longer exposure time.

---

### 4. Focal Length and Focus
**Focal length** (e.g. 16 mm, 25 mm, 50 mm) determines how zoomed-in the image is.
It is fixed by which lens is physically mounted — you don't change it in software.
- Short focal length (16 mm) = wide angle, sees more of the dish, objects appear smaller
- Long focal length (50 mm) = narrow angle, zooms in, objects appear larger

**Focus** is the physical focus ring on the lens. Turn it until the specimen edges are sharp.
Once set for a fixed camera-to-dish distance, you lock it and never touch it again.

**For this project:**
- Overhead camera: fixed distance from camera to dish surface. Set focus once, lock it.
- EoA camera (end-of-arm): mounted on robot — focus is set for the close-up working distance
  (few cm from specimen). Ring light on EoA camera illuminates from the front.

**In arena_api:** focal length and focus are NOT software-controllable. Physical lens only.

---

### 5. Pixel Format
**What it is:** how colour is encoded per pixel.
- `Mono8` — grayscale, 1 byte per pixel. Good for backlight silhouette imaging.
- `BGR8` — full colour, 3 bytes per pixel (Blue, Green, Red). What we use now.
- `BayerRG8` — raw colour sensor data, needs software demosaic to become a colour image.

**For this project:**
- Overhead camera: `BGR8` for colour images (confirmed working today).
- The TRI245S-C is a colour sensor. `BGR8` gives you proper colour with no extra steps.

**In arena_api:**
```python
nm["PixelFormat"].value = "BGR8"
```

---

### 6. Auto vs Manual — what to do for production

| Setting | During testing | In production (final software) |
|---------|---------------|-------------------------------|
| ExposureAuto | Continuous (let camera adapt) | Off — fixed value determined during calibration |
| GainAuto | Continuous | Off — fixed at 0 dB |
| PixelFormat | BGR8 | BGR8 (overhead) / BGR8 (EoA) |
| Aperture | Set physically on lens | Locked — never touch again |
| Focus | Set physically on lens | Locked — never touch again |

The reason to lock everything in production: the vision pipeline needs consistent pixel values
to threshold specimens reliably. If exposure changes between frames, the threshold breaks.

---

### 7. Quick cheat sheet — what to check when image looks wrong

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| All white / blown out (mean > 220) | Exposure too long or gain too high | Reduce ExposureTime, set Gain=0 |
| All black (mean < 5) | Lens cap on, light off, or exposure too short | Check physical setup first |
| Grainy / noisy | Gain too high | Set Gain=0, increase ExposureTime instead |
| Blurry | Focus ring not set | Physically adjust focus ring on lens |
| Sharp centre, blurry edges | Aperture too large (low f-number) | Close aperture (higher f-number) |
| Image too zoomed in/out | Wrong focal length lens | Physical lens swap |
| Colour looks wrong | Wrong PixelFormat or white balance | Use BGR8, check white balance nodes |

## 6. Robot I/O — New Info from Tejas (June 14)

### Ring light (EoA camera illumination)
- **NOT a standalone controller** — the ring light is wired into the **Epson robot's digital outputs**
- To turn it ON: on the teach pendant → Outputs → set **Output 12 = ON**
- In software: send the robot a command to set Output 12 high
- This means the ring light can only be used when the robot driver is active and connected
- The EoA camera ring light and robot are tightly coupled — you cannot test the ring light
  independently of the robot

### Pipette up/down (pneumatic)
- Controlled via **robot Output 4**
- Mechanism: **pressure/pneumatics** move the pipette up and down (not a motor)
- Output 4 ON = pipette moves (up or down — confirm direction with David)
- This is a solenoid valve triggered by the robot's digital output

### Syringe pump (liquid handling)
- Device: **Novanta M-Drive** at 172.16.9.16
- Purpose: **sucking up and pushing down liquid inside the syringe** (aspiration/dispense)
- This is the LINEAR MOTOR — it drives the plunger inside the syringe
- The pipette tip moves pneumatically (Output 4), the liquid moves via M-Drive motor
- These are two separate mechanisms working together for each pick:
  1. Output 4 → pipette tip lowers (pneumatic)
  2. M-Drive → aspirate (pull plunger back = suck liquid/specimen up)
  3. Robot moves to destination
  4. M-Drive → dispense (push plunger forward = push specimen out)
  5. Output 4 → pipette tip raises (pneumatic)
