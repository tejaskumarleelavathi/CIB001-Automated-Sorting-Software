## 2. PLC (172.16.9.11) — Modbus Testing Results

### Connection
- Modbus TCP on port 502 ✅
- Responds to all slave IDs (0, 1, 2, 255) — PLC accepts any unit ID
- pymodbus 3.13.0 installed in `cib_env` conda environment

### Address offset — important
- Tools like QModMaster use **1-based addressing** (base address = 1)
- pymodbus uses **0-based addressing**
- So: coil "1" in QModMaster = coil address `0` in pymodbus
- Always subtract 1 when converting from tool addresses to pymodbus addresses

### What was tested
| Address | Type | Result |
|---------|------|--------|
| Coil 0 | Read | ✅ Returns `True` (was already ON — PLC has it set) |
| Coil 0 | Write ON/OFF | ✅ Works — write accepted, readback confirmed |
| Coil 1 | Write | ❌ Exception code 2 — illegal address (not in PLC program) |
| Holding registers 0–149 | Read | ✅ All return 0 (nothing mapped yet or outputs all off) |
| Input registers 0–49 | Read | ✅ All return 0 |

### Key finding
- Coil 0 responds and was already ON — likely a system status/ready bit in David's PLC program
- **No physical outputs changed** when writing coil 0 — register addresses for status light and work light still unknown (OQ-11 still open)
- Need David's PLC register map to know which addresses control the physical lights

### QModMaster issue resolved
- QModMaster was failing with "no response from slave" because of base address setting
- Fix: set base address to 0 in QModMaster (not 1), slave ID = 1, port 502

## 6. pymodbus 3.13 API Notes

Important differences from older pymodbus versions:

- `count` must be a **keyword argument**: `read_holding_registers(address=0, count=10)` not `read_holding_registers(0, 10)`
- `slave` parameter is **not accepted** on individual read/write calls in 3.13 — set at client level or omit (PLC accepts all IDs anyway)
- `write_coil(address=0, value=True)` — value is bool not int
- `write_register(address=0, value=42)` — value is int
